# tools

## check_html.py — HTML構造検査

push前と、HTMLを機械生成したあとに走らせる。依存パッケージなし（標準ライブラリのみ）。

```sh
python3 tools/check_html.py             # リポジトリ内の全HTMLを検査
python3 tools/check_html.py index.html  # ファイルを指定
python3 tools/check_html.py --quiet     # 問題がなければ何も出さない（フック用）
python3 tools/check_html.py --self-test # 既知の事故を再現し、検査が効くか確かめる
```

問題が1件でもあれば終了コード1を返す。

### なぜあるのか

2026-08-23、ショートセクションを生成する `gen_shorts_html.py`（Dropbox側）が、
差し替え範囲を `</div>\s*</section>` に一致する正規表現で決めていたため、
**次のセクションの中身まで飲み込んで削除**する事故が起きた（pushする前に気づいて復元した）。

このとき、

- **タグの対応は崩れていなかった** — 消えた範囲の中で開きと閉じが釣り合っていた
- **カードは17枚あり、枚数バッジとも一致していた**

ので、素朴な入れ子検査でもショート節の検査でも捕まらない。捕まえられるのは
「消えた節がもう無い」と言える目印だけで、それが `check_html.py` の `LANDMARKS`。

**検査項目を削るときは、必ず `--self-test` が通ることを確かめてから削ること。**

### ブロックを意図的に消したとき

`LANDMARKS` も一緒に更新する。検査が落ちたら、まず「消したのは意図的か？」を
確認する。意図していないなら直近の生成スクリプトの実行を疑う。

### 数え方の注意

`grep -c '<div'` のような素朴な数え方はしないこと。コメントやCSSに**散文として
書かれた** `<div>` まで数えてしまう（`index.html` には実際に3か所ある。これを
数えて「divが86/85でずれている」と誤診した経緯がある）。`check_html.py` は
コメントを丸ごと、`<style>`/`<script>` は中身だけをマスクしてから数えている。
`<script id="d" type="application/json">` のようにタグ自身が属性を持つことがあるので、
**タグごと潰してはいけない**。

## pre-push — push前フック

```sh
ln -sf ../../tools/pre-push .git/hooks/pre-push   # 各Macで1回だけ
git push --no-verify                              # 一時的に飛ばす
rm .git/hooks/pre-push                            # 外す
```

## 生成スクリプト側の防御

`gen_shorts_html.py`（`002 リード/999 抽出/制作物_リードα/shorts/`）には二重の防御を入れてある。

1. **範囲ガード** — 変わってよいのは `short-card` の行と枚数バッジの行だけ。
   それ以外の行が変わろうとしたら**書き出す前に**停止する。
2. **構造検査** — 書き出したあと `tools/check_html.py` を走らせ、
   失敗したら**元の内容に書き戻して**終了コード1で終わる。
